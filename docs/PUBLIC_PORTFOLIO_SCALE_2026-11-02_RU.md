# Atlas — публичный портфель и проверка масштаба (02.11.2026)

## Цель и границы

Испытать универсальный Atlas на **реальных публичных GitHub-метаданных** и синтетической предметной модели. Это **не** тест подтверждённой готовности upstream-разработок. Никаких данных закрытых репозиториев IWXA, паролей, пользовательских данных или реальных свидетельств приёмки.

Публичная рабочая ветка: `work/2026-11-01-atlas-foundation`; `main` и `Faust-S/IWXA-Atlas` не меняются.

## Набор из 12 реальных репозиториев

Источник: GitHub REST API, прочитаны в течение 01–02.11.2026. Зафиксированные ID, имена default-веток, SHA и endpoint опубликованы в `tests/fixtures/public-repos-2026-11-02.json`.

- `xyflow/xyflow`, `cytoscape/cytoscape.js`, `dexie/Dexie.js`, `frappe/gantt`.
- `vitejs/vite`, `vitest-dev/vitest`, `microsoft/playwright`, `microsoft/TypeScript`.
- `mermaid-js/mermaid`, `nodejs/node`, `python/cpython`, `apache/airflow`.

Значения SHA — **срез на момент наблюдения**, а не неизменный статус репозиториев. Только default branch: не утверждается полнота перечисления остальных веток. Отдельная GitHub Actions-проверка `ci-public-sources.mjs` читает актуальные публичные metadata и SHA через краткоживущий `github.token` только на чтение; отклонения SHA допустимы и явно показываются.

## Синтетическая предметная модель

Три воспроизводимых уровня:

| Уровень | Проектов | Работ | Требований | Источников | Межпроектных зависимостей |
|---|---:|---:|---:|---:|---:|
| Малый | 12 | 144 | 48 | 12 | 11 |
| Средний | 60 | 720 | 240 | 60 | 59 |
| Большой | 120 | 1 440 | 480 | 120 | 119 |

Каждый Atlas-проект содержит явную ссылку на один из 12 настоящих публичных репозиториев. Повторяющиеся ссылки предназначены для испытания *нескольких проектов на одном источнике*, а не для заявления, будто существует 120 разных upstream Git-репозиториев. Заявленные требования, факты, работы, роли, риски, зависимости и решения **полностью синтетические**. У них есть соответствующие метки `SYNTHETIC`. Сведения о branch heads в фикстуре **неполные** (`complete:false`), поэтому недопустимы выводы об удалении веток или готовности продукта.

## Программа испытаний

1. **Node 22**: проверка `atlas.project/1`, точного JSON roundtrip, объёма снимка, CPM, транзитивных зависимостей, очереди задач/фактов, времени исполнения и RSS на трёх размерах.
2. **GitHub REST (реальная сеть)**: двенадцать публичных репозиториев — проверить совпадение стабильного GitHub ID и наличие текущего SHA default branch; регистрировать изменения SHA между первоначальным срезом и наблюдением, не считать их дефектом.
3. **Chromium / Linux**: JSON import через настоящий UI; реальный IndexedDB; сортировка/поиск/фильтры, большие подробные графы, 2/2/6 последовательных перезагрузок браузерной страницы для уровней 12/60/120; повторный readback из IndexedDB; добавление нового проекта в большой снимок. Измерять время импорта/отрисовки, раскрытия подробных отчётов и худшего восстановления; оценить память JS heap, если доступна.
4. **Разграничение длительного хранения**: последовательные reload/readback и повторное открытие IndexedDB — это *проверка повторной загрузки*, но не многодневное испытание ресурса, дискового отказа или сохранности при удалении профиля браузера.

## Расход GitHub Actions

Обычный `push` выполняет только существующий Node CI. Однократный маркер `[scale-accept]` запускает **одну** дополнительную Linux-задачу после успешного Node CI: реальный публичный GitHub REST → Chromium. Нет постоянных тяжёлых браузерных проверок и нет матрицы трёх ОС для нагрузки (базовый пользовательский маршрут уже прошёл три ОС в предыдущей приёмке).

## Критерии и ограничения

PASS только при фактических протоколах исполнения. Не назначать заранее порогов производительности, которые не измерены на целевых устройствах. Синтетическая фикстура не доказывает подлинность содержимого репозиториев, прохождение upstream CI или степень выполнения их настоящих требований. Отдельно отмечать дефекты и верхнюю границу проверенного масштаба.

## Результат

Статусы, фактические времена, номер CI и обнаруженные дефекты вносятся **после** реального запуска.
