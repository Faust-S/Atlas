## Следующая проверка установленного EXE (новый подход)

В единственном Windows gate добавлена проверка **точного установленного NSIS EXE**, а не только release-бинарника из сборочного каталога. После установки программа дважды запускается как самостоятельный процесс с полным завершением между запусками. Уже существующая переменная наблюдаемости `ATLAS_CI_RENDERER_PROBE=1` позволяет проверить, что React/WebView2 действительно вызвал `atlas_open` в Rust; CDP и UIA не применяются. Квитанция привязана к PID и удаляется после каждого прогона.

PASS этой проверки подтверждает установленный WebView2 → Rust open и повторный запуск. **Она не является сквозной приёмкой создания и сохранения проекта через GUI**, которая остаётся HOLD до интерактивной Windows-среды. Результат запуска указывать только после получения полного статуса workflow.

Нативный экспорт JSON дополнен атомарной публикацией резервной копии без перезаписи существующего файла и проверкой поколения **после** системного диалога; перед сохранением гарантируется размер, совместимый с нативным импортом. Эти проверки не вводят нового хранилища и не меняют контракт `atlas.project/1`.

Если хост не допускает физический клавиатурный ввод или фокусировку окна, это отдельный runner HOLD, а не автоматически продуктовый дефект.

## Причина отказа штатного закрытия

В [Actions #41501546562](https://github.com/Faust-S/Atlas/actions/runs/41501546562) прошёл сквозной сценарий записи двух проектов через установленный GUI и сохранения ID при полном перезапуске, но оба закрытия окна завершились принудительным прекращением процесса.

Причина установлена по фактической реализации Tauri 2 API: `Window.onCloseRequested()` после успешного пользовательского обработчика делает `Window.destroy()`, если не вызван `preventDefault()`. Требуемого `core:window:allow-destroy` в `desktop/src-tauri/capabilities/main.json` не было. Одного `core:window:allow-close` недостаточно. Это не потеря данных и не предположение о таймере readback.

Исправлено **только** разрешение разрушения окна для локального окна `main`, необходимое штатному закрытию через событие Tauri. Новых политик пользователей, файловых, сетевых или исполнительных разрешений нет; защита несохранённого черновика продолжает вызывать `preventDefault()`.

Windows gate теперь сохраняет возможность отдельно установить PASS восстановления после аварийного завершения, но **завершается ошибкой**, если хоть одна попытка штатного закрытия потребовала `Stop-Process -Force`. Не считать исправление принятым без успешного прогона текущего NSIS.
