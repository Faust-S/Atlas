## Обнаруженный блокер

Снимки реального установленного окна (файлы `atlas-uia-initial-window.png` и `atlas-uia-create-project.png` из [артефакта CI](https://github.com/Faust-S/Atlas/actions/runs/41456134816)) показывают полностью белую область WebView2 с обычной системной рамкой Windows. Дерево доступности UIA показывает только рамку, titlebar и системные кнопки; кнопка «Создать проект» отсутствует. Это не доказательство порчи файлов Atlas и не подтверждение успешной работы интерфейса.

На более ранней редакции также не удалось открыть порт WebView2 CDP даже с `WEBVIEW2_ADDITIONAL_BROWSER_ARGUMENTS` и изолированным `WEBVIEW2_USER_DATA_FOLDER`: [41455017774](https://github.com/Faust-S/Atlas/actions/runs/41455017774). Повторять этот маршрут без новой технической гипотезы не следует.

В коммите `f55c130…` удалён дублирующий HTML CSP (Tauri CSP в `tauri.conf.json` сохранён), добавлены статический fallback загрузки, диагностика ошибок модулей и React Error Boundary. Несмотря на эти изменения, Windows CI снова показывает белую область даже вместо статического HTML. Необходимо установить, вызвано ли это ошибкой загрузки ресурсов/инициализации WebView2 либо ограничением неинтерактивной среды GitHub-hosted Windows runner. Считать причину доказанной нельзя.

## Следующий единственный необходимый gate

На интерактивной Windows (не смешивать с сервисным runner) использовать **установщик текущего HEAD** и выполнить:

1. Установка приложения через NSIS, запуск значком программы, подтверждение реального экрана Atlas без Vite/Personal Agent/HTTP-сервера.
2. Создать проект, работу, зависимость, требование и наблюдение. Сохранить вручную и увидеть подтверждение повторного чтения нативного store.
3. Полностью закрыть все процессы Atlas, открыть снова и сравнить ID, значения, историю, факт и работу.
4. Проверить изменение оценки длительности, новый расчёт CPM, решение человека, утверждение и отдельное применение изменения плана.
5. Проверить JSON импорт снимка 0.1, резервную копию, намеренно ошибочный файл (без повреждения рабочего портфеля), восстановление с согласием человека.
6. Повторить на крупном портфеле после доказанного малого маршрута, не создавая отдельные Task Engine/Host/Store.

При FAIL получить диагностику реального WebView2 NavigationCompleted/URL, затем проверить встроенные ресурсы `index.html`, CSP и модули. Не выдавать PASS только за наличие окна.
