## Уточнённая диагностика 02.11.2026

Первоначальные белые скриншоты не являются доказательством неисправности React. Последующие проверки установили:

- [41458989559](https://github.com/Faust-S/Atlas/actions/runs/41458989559) — 132/132 Node, frontend build и **реальное выполнение production DOM в Chromium PASS**.
- [41459431844](https://github.com/Faust-S/Atlas/actions/runs/41459431844) — компиляция Windows, 5/5 Rust, установка NSIS PASS. Из установленного WebView2 получена квитанция `ATLAS_TAURI_JS_NATIVE_OPEN_PASS`: React вызвал Rust-команду `atlas_open`; нативный store открылся. Windows UI Automation обнаружила `RootWebArea`, дерево React и кнопку `＋ Создать проект`. Автоматизированное нажатие не выполнено из-за ошибочного строгого поиска `Создать проект`.
- [41460850484](https://github.com/Faust-S/Atlas/actions/runs/41460850484) — извлечён реальный скриншот **оформленного интерфейса Atlas**; это уже не белое окно. Команда UIA Invoke выделила кнопку, но не открыла форму.
- [41461234634](https://github.com/Faust-S/Atlas/actions/runs/41461234634) — при проверке физического ввода старого установщика дерево WebView2 не появилось за установленный тайм-аут; наблюдается нестабильная доступность браузерной части в GitHub-hosted Windows runner.

**Подтверждено:** приложение собирается, устанавливается и способно отобразить интерфейс React в установленном Windows EXE; IPC React → Tauri/Rust и открытие store работают. Нельзя по раннему белому снимку объявлять неисправность продукта.

**Не подтверждено:** ручное создание проекта, сохранение, закрытие процесса и чтение после повторного запуска через установленный GUI. Факт прохождения 5/5 Rust относится только к нативному store и не заменяет это испытание.

Устаревшие отдельные CDP-прогоны не повторять. Временная проверка UIA на старом кандидате использовалась для диагностики и удаляется, чтобы не множить CI workflow.

## Следующий единственный необходимый gate

На интерактивной Windows (не смешивать с сервисным runner) использовать **установщик текущего HEAD** и выполнить:

1. Установка приложения через NSIS, запуск значком программы, подтверждение реального экрана Atlas без Vite/Personal Agent/HTTP-сервера.
2. Создать проект, работу, зависимость, требование и наблюдение. Сохранить вручную и увидеть подтверждение повторного чтения нативного store.
3. Полностью закрыть все процессы Atlas, открыть снова и сравнить ID, значения, историю, факт и работу.
4. Проверить изменение оценки длительности, новый расчёт CPM, решение человека, утверждение и отдельное применение изменения плана.
5. Проверить JSON импорт снимка 0.1, резервную копию, намеренно ошибочный файл (без повреждения рабочего портфеля), восстановление с согласием человека.
6. Повторить на крупном портфеле после доказанного малого маршрута, не создавая отдельные Task Engine/Host/Store.

При FAIL получить диагностику реального WebView2 NavigationCompleted/URL, затем проверить встроенные ресурсы `index.html`, CSP и модули. Не выдавать PASS только за наличие окна.

## Правила

- `release/0.1` закреплён на `addee450b8d80f8fad1fcb9af8e8d13dc1824151`.
- Desktop 0.2 использует те же `src/*.mjs`; отдельный бизнес-движок не создаётся.
- Действующий Windows gate `.github/workflows/atlas-desktop-0-2.yml` проверяет Rust/Tauri, NSIS, установку и окно. UIA/CDP на hosted runner исключены после нестабильных прогонов; полная приёмка установленного GUI остаётся **HOLD**, без выдачи CI PASS за пользовательский маршрут.
- Первое сохранение теперь оставляет восстанавливаемый манифест в истории: потеря первого `head.json` не открывает тихо пустой портфель. После второго сохранения продолжает действовать прежний механизм предыдущей редакции.
- Экспериментальные отдельные workflow CDP и UIA из разработки удалены, чтобы не запускать дублирующую квалификацию и не расходовать Actions.
- Admin Center/T3 по-прежнему отложены, приватный Atlas и `main` не менялись.
