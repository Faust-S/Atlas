# Open-source review for Atlas (2026-11-01)

This is an architectural/official-source review, **not a claim of independent performance benchmarks**.

## Evaluation principles

A product for both private persons and corporations must support predictive, agile and mixed project approaches, including goals, milestones, dependencies, budgets, resources, risks, decisions, work tracking, provenance and multi-project portfolios. The source systems remain authoritative; Atlas provides cross-system synthesis. ISO 21502:2020 and PMI's agile project-management guidance inform the requirements; their text is not copied.

## Systems examined

| Project | Reusable practices | Decision |
| --- | --- | --- |
| Plane — https://github.com/makeplane/plane | Workspace/issue/cycle/module views and clean UX | UX reference; do not fork a large AGPL project with its own task database |
| OpenProject — https://github.com/opf/openproject | Gantt, enterprise scheduling, portfolios, cost controls | Feature reference; do not import GPL-heavy server |
| Leantime — https://github.com/Leantime/leantime | Goals, strategy, milestones, risks, idea management | Conceptual reuse; avoid PHP/MySQL/AGPL monolith |
| Vikunja — https://github.com/go-vikunja/vikunja | Personal simplicity, lists/boards/calendars | Feature reference; avoid another task engine |
| WeKan — https://github.com/wekan/wekan | Mature Kanban UX, board operations; MIT | Study small interaction patterns; avoid Meteor platform fork |
| Kanboard — https://github.com/kanboard/kanboard | Small Kanban, plugins, MIT | Not a good universal base; maintenance-focused |
| React Flow (xyflow) — https://github.com/xyflow/xyflow | Node/edge UI | Candidate MIT visual component, not yet bundled |
| Frappe Gantt — https://github.com/frappe/gantt | Gantt timeline | Candidate MIT visual component, not yet bundled |

Review exact licenses and dependency trees before copying code. Source availability does not imply all paid features are included or that private code/data may be published.

## Decision

**Own the small project model and adaptation boundary; reuse targeted permissive visualization components.** This avoids duplicating Task Engine, the agent's Programs Center and proprietary domain contracts. Build generic public Atlas first, then operate it on actual IWXA projects in a private deployment. Allow human and multiple agent executor references, including Hermes, with execution through existing authorized systems.

## Outcome-oriented project synthesis

A dashboard must answer more than “what branches exist?” It must explain project goals, deliverables, actual accepted progress, risk, critical dependencies, next decisions and freshness with exact source links. New Git branches are automatically discoverable *when authorized enumeration exists*, but do not automatically imply new product readiness.
