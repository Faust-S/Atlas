# IWXA Atlas 0.8 - разработка

Начало: 14 ноября 2026 года.
Рабочая ветка: `work/2026-11-14-atlas-0-8`.
Основа: `release/0.7`, SHA `16111a64140a2885a22393e2c883684b008f5eff`.

## Стабильная основа

Atlas 0.7.0 выпущен с установщиком Setup Core, подтверждённой
Windows-приёмкой, сохранением и холодным восстановлением. Выпуск
не изменяется. Версия 0.8 пока находится в разработке.

## Первый пользовательский пробел

Человек помнит несколько слов из названия работы, но не точный
порядок. Например, `1080 работа 5` раньше не находило сохранённую
`Работа 5 / 1080`. Теперь поиск по проектам, таблице работ
и схеме работ допускает другой порядок слов внутри одного поля.

Разные поля не соединяются искусственно. Слова из работы и слова
из другого этапа сами по себе не являются совпадением.
Связанный источник и каталог, как и раньше, образуют одну реально
сохранённую пару. Прямое действие `К работе` показывается только
для единственной подходящей работы в единственном проекте.

Поиск не меняет проект, зависимости, Store, версии источников
и данные `.iwxa`. Для проверки предусмотрен отдельный адресный
тест `tests/atlas08-flexible-lookup.test.mjs`.

## Дальнейшая разработка

Улучшать подключение, развёртывание, управление и визуализацию
проекта любого назначения. Не создавать новый Core, Store,
Task Engine, IAM и неподтверждённые предметные связи.

Перед новыми изменениями проверять свежие HEAD/TREE, инструкции
репозитория, `docs/ARCHITECTURE.md` и авторский тон IWXA.
Доступные исходные проверки выполняются самостоятельно.
Windows-приёмка и публикация релиза выполняются отдельно;
обычный PASS Node не означает готовый установщик.

## Продолжение 15 ноября 2026 года

Из поиска по портфелю теперь можно сразу открыть сохранённые работы
по найденному этапу, каталогу или названию. Результат открывается
в существующей таблице с прежним запросом, без второго поиска.
Если найдено несколько проектов, ссылка на соответствующие работы
есть у каждого результата, в том числе в полной таблице портфеля.
Если проект совпал по названию или владельцу, а работ по запросу
нет, пустая ссылка на работы не показывается.

При однозначном совпадении названия работы сохранён прямой переход
к конкретной работе. Открытие таблицы очищает несвязанные с поиском
фильтры через штатное переключение проекта. Навигация не сохраняет
и не меняет записи. Добавлен регрессионный файл
`tests/atlas08-portfolio-work-navigation.test.mjs`.
Исходная проверка этого участка: GitHub Actions №43700980657,
SUCCESS, SHA `6a4a5509`.

Рабочая версия приложения, Tauri, Rust, npm/Cargo lock и профиль
Setup Core согласованы как `0.8.0-dev.1`. На пользовательском
экране должна показываться надпись `0.8.0 (разработка)`, а не
`0.7.0`, чтобы разработческая сборка не выглядела стабильным
релизом. Нового установщика для пользователя пока нет.

После изменения номера версии исправлены прежние тестовые ожидания
в проверках Setup Core, маркировки и установленного приложения.
Сохраняются отдельные проверки исходной релизной цепочки 0.7
и завершённого выпуска 0.6. Итоговый результат проверки полного
HEAD определяется только последним выполненным CI. Windows
проверяется при подготовке выпуска 0.8, не после каждой функции.


## Возврат к выбранной работе после просмотра связей и источников

При переходе из таблицы к зависимостям `view("graph")` сбрасывал
отбор критических и затронутых работ. После возврата список менялся.
Исправление опубликовано в 0.8: перед выходом из таблицы Atlas
запоминает поиск, все действующие фильтры, сортировку, лимит
показанных работ и идентификатор выбранной работы. Возврат
из схемы связей или источника восстанавливает исходный список
и фокусирует прежнюю работу.

Маршрут через несколько разделов тоже учитывается:
таблица -> связи -> источник -> связи -> таблица.
Возврат к графу из источника не перезаписывает первоначальный
контекст таблицы. При изменении проекта или его редакции
контекст сбрасывается; нельзя восстановить заведомо устаревшую
выборку после изменения плана. Использован только временный
`useRef` интерфейса, без новых записей в Store и `.iwxa`.

Проверка GitHub Actions №43702099460 на `01fcaf64`:
Node 642/642 PASS, Python-проверка носителя `.iwxa` PASS,
контракт Center PASS, TypeScript/Vite PASS. Это проверка
исходников и сборки, не нативная Windows-приёмка.


## Предварительный расчёт изменения работы до применения

Реализован пользовательский маршрут: открыть существующую работу,
изменить длительность или контрольный срок и сразу увидеть последствия
в редакторе. До подтверждения формы Atlas показывает общую
продолжительность проекта до/после, финиш выбранной работы, число
затронутых работ, сдвиги, изменение критического пути и соблюдение
контрольного срока. Если календарная дата начала проекта не установлена,
факт соблюдения срока не придумывается. Снятие контрольного срока
не считается устранением нарушения.

Прогноз рассчитывает `src/work-schedule-preview.mjs` через
существующий `scheduleProject` + `scheduleChangeSummary`.
Только изменённая работа копируется во временную проекцию. При
некорректном вводе прогноз не строится. При вводе имени,
ответственного и других неплановых полей повторного расчёта нет.
Изменения по-прежнему применяются исключительно штатной кнопкой
«Применить к черновику», а записываются на диск отдельно.
Новый Store, исполнительный движок и .iwxa-формат не создавались.

Блок встроен в существующий инспектор, не перекрывает нижние кнопки
на компактных экранах Windows. Детали затронутых работ разворачиваются
по желанию. Независимое сравнение на большом сохранённом примере
сопоставляет прогноз и результат реального `applyEditor`.

Исходная квалификация: GitHub Actions №43702741310,
коммит `883463fc649d4612364ac3f3ac012b43d15b245e`,
648/648 Node PASS, TypeScript/Vite PASS,
проверка носителя .iwxa PASS, настоящий контракт Center PASS.
Релиз 0.7.0 остался на `16111a64`. Отдельная
нативная Windows-квалификация 0.8 ещё не выполнялась.

редактирования затронутой работы без потери исходного контекста
и проверить итоговую Windows-сборку ближе к релизу 0.8.
