# Atlas — настоящая браузерная приёмка, 2026-11-02

## Область
Публичный репозиторий `Faust-S/Atlas`, рабочая ветка `work/2026-11-01-atlas-foundation`. Ни `main`, ни приватный `IWXA-Atlas` не изменяются.

Используется настоящий Chromium в GitHub-hosted runner. Одно приложение и одно встроенное IndexedDB-хранилище; Playwright установлен только внутри CI и не входит в продукт.

## Последовательность и экономия GitHub

1. `qualify` — Ubuntu Node 22, `npm test`, проверка синтаксиса.
2. `browser-linux` — Ubuntu Chromium, только после PASS Node.
3. `browser-cross-os` — Windows и macOS Chromium, только после PASS Linux.

Дорогой маршрут выполняется **только** через `workflow_dispatch` или одноразовый маркер `[browser-accept]` в сообщении коммита. Обычные изменения запускают только короткие Node-проверки. Запуски с новыми коммитами отменяют устаревшие; артефакты сохраняются только при сбое на 3 дня.

## Реальные пользовательские действия

- Открытие публичного Atlas на HTTP loopback, проверка отсутствия ошибок браузера.
- Native IndexedDB: миграция `localStorage`, контроль целостности, восстановление повреждённого снимка, отказ устаревшей вкладке.
- Создание проекта и обязательного требования; создание двух работ, связь, критический граф.
- Добавление публичного GitHub-владельца, обнаружение репозитория, подключение и получение имён веток и SHAs.
- Создание факта на точной Git-ревизии; изменение наблюдаемого SHA и проверка, что старое свидетельство остаётся привязанным к старой ревизии.
- Блокировка работы, предложение изменения, утверждение человеком с обоснованием, создание связанной работы.
- Перезапуск приложения и фактический readback из IndexedDB.
- Создание второго проекта и межпроектной зависимости, визуальный граф, переход из портфельной очереди к требованиям.
- Экспорт реального JSON через браузер, изменение данных, импорт предыдущей копии, повторный запуск.
- Проверка стартовой страницы при ширине 390 px.

Сверка GitHub проводится через **локально подменённый публичный REST fixture** внутри настоящего браузера: проверяется контракт, CORS, код UI, запись provenance и реакция на изменения SHA. Это не является проверкой сетевой доступности внешнего GitHub API или доступом к приватным репозиториям. В fixture не используются токены или закрытые сведения.

## Критерии PASS

Только успешное завершение jobs на **всех трёх ОС** при одном и том же commit SHA и совпадающий readback данных. Node PASS не заменяет Chromium PASS. Любая ошибка браузера, некорректный SHA, потеря связей/решений после перезапуска, несоответствие восстановленного JSON и отказ Native IndexedDB должны завершать браузерный job с FAIL.

Фактические статусы, номера запусков, SHA и выявленные дефекты фиксируются после завершения реального CI, а не заранее.
