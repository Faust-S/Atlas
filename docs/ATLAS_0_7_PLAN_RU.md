# Atlas 0.7. Разработка

Старт: 12 ноября 2026 года.
Рабочая ветка: `work/2026-11-12-atlas-0-7`.
Основа: `release/0.6`. Atlas 0.6.0 официально опубликован
12 ноября 2026 года. Ветка 0.6 закрыта для дальнейшей разработки;
новая функциональность создаётся только в `work/2026-11-12-atlas-0-7`.

## Цель

Человек должен подключать, разворачивать, вести и понимать проект
любого назначения: личный, организационный, исследовательский или
программный. IWXA остаётся примером большого проекта, но не определяет
пользовательский интерфейс Atlas.

## Первый участок

Раньше переход «Подключить источник» в составе проекта зависел от
типа «Инженерный». Теперь он доступен любому проекту без источников,
в том числе только что созданному. Для подключения используется
имеющийся раздел «Источники», без нового хранилища и без автоматического
создания работ. Просмотр и переход сами по себе ничего не сохраняют.

Критерии: доступность в обычном Windows-проекте без GitHub, переход
к действующему экрану источников, обратная навигация, неизменность
локального хранилища. Проверка исходников дополняется квалификацией
установленного продукта.

## Далее по приоритетам

1. Удобство выбора и подтверждённой связи источников с работами.
2. Единый понятный обзор больших и малых проектов, без жаргона.
3. Наглядное управление изменениями проекта и сохранением результата.
4. Работа через существующие порты Agent/Admin/T3, когда контракты
   готовности подтверждены, без нового Core или исполнительного движка.

Не добавлять неподтверждённые зависимости, исполнение задач по факту
отображения в Atlas, двойную синхронизацию и скрытые записи.


## Проверенные результаты 0.7

- Первый переход к источникам в обычном проекте без GitHub: Windows PASS.
- Привязка существующей работы к наблюдаемому каталогу, сохранение,
  восстановление после перезапуска: Windows PASS, Actions #43248683244.
- Снятие ошибочной привязки через существующий редактор: исходники и
  нативная Windows-проверка добавлены, до результата квалификации кандидат.


## Следующий функциональный участок: поиск всех актуальных каталогов

Windows-квалификация #43294299595 на HEAD 3f9839fb прошла полностью,
включая связку существующей работы, снятие неверной привязки, поиск
работы в большом списке и обычный проект без GitHub.

Краткая схема показывает только несколько источников и каталогов.
Человек не должен угадывать, какие источники скрыты после изменения
числа связей. Добавлен единый поиск по работам, этапам и актуально
наблюдаемым каталогам *всего проекта*, включая не показанные в
краткой схеме. Найденный каталог можно напрямую привязать к уже
существующей работе через прежнюю форму. Сведения прежней редакции,
неполные и недоступные источники не дают права на запись; обычная
проверка выбранного каталога выполняется при применении формы заново.
Поиск ничего не записывает. Нативная проверка включает обычное
сохранение и повторный запуск после выбора скрытого каталога.


## Отображаемая версия установленной программы

Маркировка рабочего Atlas больше не зашита в интерфейс отдельно от
версии сборки. На экране загрузки, в заголовке и внизу окна
показывается версия из desktop/package.json, согласованная с
нативной конфигурацией Tauri. До релиза рядом явно написано
«разработка». Установщик остаётся версией 0.7.0-dev.1,
стабильный Atlas 0.6.0 не изменяется.


В пустом плане найденный каталог предлагает сразу «Создать работу»,
а не открыть список несуществующих работ. Используется тот же
обычный редактор создания работы. При наличии работ предлагается
«Связать работу». Выбор не записывает данные без сохранения.


## Неполные наблюдения источников

Если в сохранённом наблюдении источник сообщает о неполном списке
каталогов, Atlas показывает предупреждение в поиске. Уже
наблюдаемый каталог с подтверждённой редакцией остаётся доступен
для явной привязки. Каталоги, которых в наблюдении нет, не
выдумываются и не считаются отсутствующими. Для обновления
доступен существующий экран источников.


## Поиск работ внутри большого проекта

В таблице проекта поиск по названию и ответственному дополнен
поиском по названию этапа, каталогу и подключённому источнику.
Поиск использует существующие записи работ и не зависит от краткой
схемы. Он применяется совместно с фильтрами состояния, требований,
сроков, наблюдений и зависимостей, не меняя сортировку и не записывая
новые данные. Регрессия рассчитана на 1212 работ, 48 этапов и 6
источников. Установленная Windows-программа должна показать результаты
по этапу и каталогу, открыть найденную работу и подтвердить
отсутствие скрытой записи.

## Независимые входы в импорт .iwxa

Если при первом подключении GitHub публичный API временно
недоступен, тест не объявляет такое подключение успешным.
Проверка импорта большого проекта не должна зависеть от этого:
при пустом портфеле используется уже существующая команда
«Открыть архив .iwxa» на начальном экране; при сохранённых
проектах используется меню «Сохранение и копии». Оба маршрута
содержат обычный выбор файла, предварительный просмотр и
явное сохранение. Дублирующееся название команд не мешает выбору.


## Сброс фильтров работ

После поиска по каталогу, этапу или ответственному можно одной
командой «Сбросить фильтры» вернуться ко всем работам проекта.
Она также убирает фильтр просроченных работ, наблюдений и зависимостей,
которые могли быть выставлены при переходах из других разделов.
Выбранный порядок сортировки сохраняется, данные проекта не изменяются.
В большом установленном проекте проверяется возврат от найденных
работ к общему списку без сохранения.


## Результат Windows-квалификации таблицы и обработка UI Automation

Windows Actions #43316445670 на HEAD 5bd71a5e: большой проект,
импорт .iwxa, сохранение, изменения связей и каталогов, снятие
привязки и поиск скрытого каталога завершились PASS. Последний
сценарий таблицы остановился при чтении дерева доступности:
pywinauto пытался создать обёртку временного элемента WebView2
без control_type и получил KeyError(None), до проверки результатов
поиска. На чтении текста теперь используется исходное дерево
UI Automation и реальные имена элементов без обязательного создания
обёртки каждого узла. Ни одна ошибка приложения этим не скрывается;
поиск и открытие работы проверяются теми же настоящими контролами,
с сохранением исходной редакции проекта.

Также в таблице добавлена явная команда «Сбросить фильтры»,
которая не меняет сортировку и не записывает данные в Store.


## Доступность сброса фильтров в длинном списке

Windows Actions #43322443327 на HEAD 76752690 подтвердил физический
поиск по этапу и по 44 работам сохранённого каталога, открытие работы
и отсутствие скрытой записи. Последний шаг не смог добраться до
кнопки сброса, оставшейся над прокрученной таблицей.

В Atlas 0.7 блок «Сбросить фильтры» находится в одной компактной
закреплённой полосе списка, под верхней командной строкой. После
возвращения из редактора к далёкой работе кнопка остаётся доступна
мышью и клавиатурой; фильтры по-прежнему сбрасываются одним
действием без изменения сортировки и без сохранения данных.
Нативная квалификация проверяет доступность кнопки без принудительной
прокрутки и точный возврат ко всем работам.


## Поиск проекта по содержимому портфеля

В большом портфеле не требуется помнить название проекта:
единая строка поиска в шапке и существующий список проектов
находят проект по имени работы, этапу, ответственному, названию
источника или паре источник/каталог. Поиск использует сохранённые
данные, не подключается к сети и не создаёт копии проекта или
новое хранилище. Текущий статусный фильтр продолжает применяться.
В Windows проверяется поиск установленного проекта по работе
№1080 и по источнику с последующим открытием проекта, без записи.


## Исправление Windows-проверки выборки из длинной таблицы

Actions #43330507932 на HEAD 8c5a6bd1 подтвердил установленный
Atlas, большой проект, связывание и снятие привязки, поиск каталогов
и 44 сохранённые работы по выбранному каталогу. Скриншоты подтвердили,
что закреплённый сброс фильтров видим вверху окна при прокрутке.
Последний сценарий пытался открыть заранее заданную работу №48,
находящуюся вне видимой области отсортированной таблицы.
Проверка теперь выбирает из сохранённого списка действительную
видимую работу по её собственному UIA-имени, открывает её мышью
и возвращается к закреплённому действию. Критерии применения,
сохранения и физической доступности кнопки не ослаблены.


## Очистка строки поиска в установленном Windows Atlas

Сценарий нового поиска по портфелю возвращает человека от
безрезультатного запроса ко всем проектам. В Windows-драйвере
исправлен ввод пустой строки: выделенный Ctrl+A текст стирается
обычным Backspace. Отдельно проверяется очищение поля,
восстановление списка, и отсутствие изменений в сохранённом Store.
Нативная проверка по-прежнему использует физический ввод.

## Поиск проектов: результат виден без прокрутки

В Windows Actions №43333227169 на коммите 110222ce все ранее принятые
сценарии установленного Atlas прошли, включая таблицу и сброс фильтров.
Поиск по работе №1080 отобразил сохранённый проект в боковой панели,
но ожидавшийся счётчик был расположен ниже блока «Что требует внимания».
В окне 1024×768 он не попадал в видимую часть при поиске.

Теперь результат поиска показывается непосредственно под заголовком
«Портфель проектов»: число совпадений видно сразу, в том числе ноль,
а при очистке поля отображается число проектов в списке. Данные
поиска и хранилище не изменяются. Windows проверяет эти надписи
настоящим вводом, затем открывает проект и сверяет сохранённую редакцию.


## Полное имя результата поиска в Windows UI Automation

Windows Actions №43404365035 на HEAD e323f525 остановился на поиске
по портфелю, хотя приложенный снимок окна 1024×768 показывает
«Найдено проектов: 1» при поиске работы №1080. Проблема в
доступности сообщения: подпись и количество формировались двумя
соседними текстовыми узлами, которые WebView2 мог отдавать в
UI Automation раздельно.

Теперь одна готовая строка используется и как видимый текст,
и как доступное имя поля состояния. Поиск, сортировка, сохранение
и данные проекта не изменяются. Проверка снова должна увидеть
результат настоящего пользовательского ввода, включая отсутствие
совпадений и возвращение к полному портфелю.


## Возврат к полному портфелю после поиска

После поиска по работе, этапу или репозиторию рядом с количеством
результатов показывается «Показать все проекты». Эта команда
сбрасывает строку запроса, восстанавливает полный список и
возвращает фокус в поле поиска. Она доступна и когда результатов
нет, без прокрутки через блок «Что требует внимания».
В Windows проверяется физическое нажатие и отсутствие записей
в локальном хранилище.
