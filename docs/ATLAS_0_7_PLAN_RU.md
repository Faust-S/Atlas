# Atlas 0.7. Разработка

Старт: 12 ноября 2026 года.
Рабочая ветка: `work/2026-11-12-atlas-0-7`.
Основа: `release/0.6`. Atlas 0.6.0 официально опубликован
12 ноября 2026 года. Ветка 0.6 закрыта для дальнейшей разработки;
новая функциональность создаётся только в `work/2026-11-12-atlas-0-7`.

## Цель

Человек должен подключать, разворачивать, вести и понимать проект
любого назначения: личный, организационный, исследовательский или
программный. IWXA остаётся примером большого проекта, но не определяет
пользовательский интерфейс Atlas.

## Первый участок

Раньше переход «Подключить источник» в составе проекта зависел от
типа «Инженерный». Теперь он доступен любому проекту без источников,
в том числе только что созданному. Для подключения используется
имеющийся раздел «Источники», без нового хранилища и без автоматического
создания работ. Просмотр и переход сами по себе ничего не сохраняют.

Критерии: доступность в обычном Windows-проекте без GitHub, переход
к действующему экрану источников, обратная навигация, неизменность
локального хранилища. Проверка исходников дополняется квалификацией
установленного продукта.

## Далее по приоритетам

1. Удобство выбора и подтверждённой связи источников с работами.
2. Единый понятный обзор больших и малых проектов, без жаргона.
3. Наглядное управление изменениями проекта и сохранением результата.
4. Работа через существующие порты Agent/Admin/T3, когда контракты
   готовности подтверждены, без нового Core или исполнительного движка.

Не добавлять неподтверждённые зависимости, исполнение задач по факту
отображения в Atlas, двойную синхронизацию и скрытые записи.


## Проверенные результаты 0.7

- Привязка существующей работы к наблюдаемому каталогу, сохранение,

- Снятие ошибочной привязки через существующий редактор: исходники и

## Следующий функциональный участок: поиск всех актуальных каталогов

Windows-квалификация #43294299595 на HEAD 3f9839fb прошла полностью,
включая связку существующей работы, снятие неверной привязки, поиск
работы в большом списке и обычный проект без GitHub.

Краткая схема показывает только несколько источников и каталогов.
Человек не должен угадывать, какие источники скрыты после изменения
числа связей. Добавлен единый поиск по работам, этапам и актуально
наблюдаемым каталогам *всего проекта*, включая не показанные в
краткой схеме. Найденный каталог можно напрямую привязать к уже
существующей работе через прежнюю форму. Сведения прежней редакции,
неполные и недоступные источники не дают права на запись; обычная
проверка выбранного каталога выполняется при применении формы заново.
Поиск ничего не записывает. Нативная проверка включает обычное
сохранение и повторный запуск после выбора скрытого каталога.


## Отображаемая версия установленной программы

Маркировка рабочего Atlas больше не зашита в интерфейс отдельно от
версии сборки. На экране загрузки, в заголовке и внизу окна
показывается версия из desktop/package.json, согласованная с
нативной конфигурацией Tauri. До релиза рядом явно написано
«разработка». Установщик остаётся версией 0.7.0-dev.1,
стабильный Atlas 0.6.0 не изменяется.


В пустом плане найденный каталог предлагает сразу «Создать работу»,
а не открыть список несуществующих работ. Используется тот же
обычный редактор создания работы. При наличии работ предлагается
«Связать работу». Выбор не записывает данные без сохранения.


## Неполные наблюдения источников

Если в сохранённом наблюдении источник сообщает о неполном списке
каталогов, Atlas показывает предупреждение в поиске. Уже
наблюдаемый каталог с подтверждённой редакцией остаётся доступен
для явной привязки. Каталоги, которых в наблюдении нет, не
выдумываются и не считаются отсутствующими. Для обновления
доступен существующий экран источников.


## Поиск работ внутри большого проекта

В таблице проекта поиск по названию и ответственному дополнен
поиском по названию этапа, каталогу и подключённому источнику.
Поиск использует существующие записи работ и не зависит от краткой
схемы. Он применяется совместно с фильтрами состояния, требований,
сроков, наблюдений и зависимостей, не меняя сортировку и не записывая
новые данные. Регрессия рассчитана на 1212 работ, 48 этапов и 6
источников. Установленная Windows-программа должна показать результаты
по этапу и каталогу, открыть найденную работу и подтвердить
отсутствие скрытой записи.

## Независимые входы в импорт .iwxa

Если при первом подключении GitHub публичный API временно
недоступен, тест не объявляет такое подключение успешным.
Проверка импорта большого проекта не должна зависеть от этого:
при пустом портфеле используется уже существующая команда
«Открыть архив .iwxa» на начальном экране; при сохранённых
проектах используется меню «Сохранение и копии». Оба маршрута
содержат обычный выбор файла, предварительный просмотр и
явное сохранение. Дублирующееся название команд не мешает выбору.


## Сброс фильтров работ

После поиска по каталогу, этапу или ответственному можно одной
командой «Сбросить фильтры» вернуться ко всем работам проекта.
Она также убирает фильтр просроченных работ, наблюдений и зависимостей,
которые могли быть выставлены при переходах из других разделов.
Выбранный порядок сортировки сохраняется, данные проекта не изменяются.
В большом установленном проекте проверяется возврат от найденных
работ к общему списку без сохранения.

поиск и открытие работы проверяются теми же настоящими контролами,
с сохранением исходной редакции проекта.

Также в таблице добавлена явная команда «Сбросить фильтры»,
которая не меняет сортировку и не записывает данные в Store.


## Доступность сброса фильтров в длинном списке

Windows Actions #43322443327 на HEAD 76752690 подтвердил физический
поиск по этапу и по 44 работам сохранённого каталога, открытие работы
и отсутствие скрытой записи. Последний шаг не смог добраться до
кнопки сброса, оставшейся над прокрученной таблицей.

В Atlas 0.7 блок «Сбросить фильтры» находится в одной компактной

возвращения из редактора к далёкой работе кнопка остаётся доступна
мышью и клавиатурой; фильтры по-прежнему сбрасываются одним
действием без изменения сортировки и без сохранения данных.
Нативная квалификация проверяет доступность кнопки без принудительной
прокрутки и точный возврат ко всем работам.


## Поиск проекта по содержимому портфеля

В большом портфеле не требуется помнить название проекта:
единая строка поиска в шапке и существующий список проектов
находят проект по имени работы, этапу, ответственному, названию
источника или паре источник/каталог. Поиск использует сохранённые
данные, не подключается к сети и не создаёт копии проекта или
новое хранилище. Текущий статусный фильтр продолжает применяться.
В Windows проверяется поиск установленного проекта по работе
№1080 и по источнику с последующим открытием проекта, без записи.

## Очистка строки поиска в установленном Windows Atlas

Сценарий нового поиска по портфелю возвращает человека от
безрезультатного запроса ко всем проектам. В Windows-драйвере
исправлен ввод пустой строки: выделенный Ctrl+A текст стирается
обычным Backspace. Отдельно проверяется очищение поля,
восстановление списка, и отсутствие изменений в сохранённом Store.
Нативная проверка по-прежнему использует физический ввод.

В Windows Actions №43333227169 на коммите 110222ce все ранее принятые

## Полное имя результата поиска в Windows UI Automation

Windows Actions №43404365035 на HEAD e323f525 остановился на поиске
по портфелю, хотя приложенный снимок окна 1024×768 показывает
«Найдено проектов: 1» при поиске работы №1080. Проблема в
доступности сообщения: подпись и количество формировались двумя
соседними текстовыми узлами, которые WebView2 мог отдавать в
UI Automation раздельно.

Теперь одна готовая строка используется и как видимый текст,
и как доступное имя поля состояния. Поиск, сортировка, сохранение
и данные проекта не изменяются. Проверка снова должна увидеть
результат настоящего пользовательского ввода, включая отсутствие
совпадений и возвращение к полному портфелю.


## Возврат к полному портфелю после поиска

После поиска по работе, этапу или репозиторию рядом с количеством
результатов показывается «Показать все проекты». Эта команда
сбрасывает строку запроса, восстанавливает полный список и
возвращает фокус в поле поиска. Она доступна и когда результатов
нет, без прокрутки через блок «Что требует внимания».
В Windows проверяется физическое нажатие и отсутствие записей
в локальном хранилище.


## Поиск на компактном экране Windows

Квалификация «Показать все проекты» включает окно 820×650:
результат нулевого поиска и кнопка сброса должны быть физически
видны без автоматической прокрутки. После нажатия полный список
восстанавливается, окно возвращается к штатному размеру и
сохранённая редакция проекта сверяется с исходной.


## Почему проект найден

В портфеле из десятков или сотен проектов поисковая строка
показывает не только название найденного проекта, но и причину:
например, «Работа: Название работы», «Этап: Подготовка» или
«Источник: репозиторий». Для совпадения по каталогу показывается
сохранённая связка источника и каталога. Сообщение появляется
под названием проекта только при активном поиске, длинные пути
не раздвигают таблицу. Все сведения берутся из сохранённого
проекта, без дополнительных загрузок и новых компонентов
хранения. Результат остаётся доступен для обычного перехода
к проекту.


## Прямой переход к единственному найденному проекту

Если поиск по работе, этапу или исходникам оставил ровно один
проект, результат появляется у заголовка портфеля: название,
причина совпадения и «Открыть проект». Не нужно искать строку
проекта за блоком внимания и прокручивать таблицу. Та же причина
остаётся показана под названием каждой найденной записи в
полной таблице, если проектов несколько. Длинные названия и
пути обрезаются визуально без потери полного значения в подсказке.
На Windows 820×650 проверяется физическое нажатие прямой команды,
открытие правильного проекта и отсутствие фоновых записей.


## «Показать все проекты» действительно показывает все состояния

При переходе к полному портфелю сбрасывается не только поисковая
строка, но и ранее выбранный фильтр состояния. Поэтому закрытые и
отменённые проекты не остаются неожиданно скрытыми под командой
«Показать все проекты». Это изменение состояния интерфейса:
данные проекта и сортировка не меняются.

## К нескольким найденным проектам без прокрутки

Когда поиск находит два и более проекта, первые три результата
показываются рядом со счётчиком: название, конкретная причина
совпадения и самостоятельное действие «Открыть проект».
Остальные результаты остаются в полной таблице. Никакой новый
индекс, порядок сортировки или сохранённые данные не создаются.

## Переход к конкретной работе из портфеля

Если в единственном найденном проекте запрос однозначно совпал
с названием ровно одной работы, рядом с действием «Открыть проект»
появляется «К работе». Переход открывает существующую таблицу,
находит нужную работу и переводит на неё фокус, в том числе
для работы в конце большого плана. При неоднозначном запросе,
совпадении по этапу или источнику эта команда не показывается.
Поиск, переход и изменение фокуса не сохраняют данные.
Windows-квалификация должна физически проверить этот маршрут
на работе №1080 при размере окна 820 × 650 и сверить Store.


## Переход от найденной работы к записанному источнику

Работа с сохранённой привязкой получила команду «Сведения об источнике»
прямо в таблице. Она открывает существующий раздел «Источники», показывает
записанный каталог и состояние наблюдения, не принимая устаревшие данные
за текущие. У работы без привязки этой команды нет. «К работе»
возвращает к той же записи и её поисковому запросу.

Проверка на установленном Windows Atlas: портфель → работа №1080 →
источник → эта же работа, физические кнопки при 820 × 650 и сверка
неизменности Store. Новых записей и фоновых обновлений нет.


## Сквозная навигация между работой, связями и источником

В представлении «Зависимости» у выбранной работы с записанным
источником доступна команда «К источнику работы». Она открывает
существующую карточку каталога с указанием наблюдаемой редакции.
«К связям работы» возвращает к той же выделенной работе на схеме,
а уже существующий переход «К работе в таблице» возвращает
первоначальный поиск и фокус в списке работ.

Маршрут не создаёт новые связи, не обновляет источник автоматически,
не принимает наблюдение за фактический результат и не записывает
изменения. Для работы без источника лишняя команда отсутствует.
Нативная Windows-проверка должна пройти полный круг на работе №1080
в окне 820 × 650 и сверить сохранённый Store до и после.


## Все затронутые работы после изменения плана

Раньше сравнение расписаний показывало только четыре примера даже при
десятках сдвинутых работ. Теперь тот же расчёт возвращает полный список
ID затронутых работ с приоритетом уже установленного порядка:
нарушения контрольных сроков, устранённые нарушения, изменение сроков,
задержки и величина сдвига.

Команда «Все затронутые работы» временно показывает именно эти
записи в существующей таблице, с привычными действиями редактирования.
Количество строк не ограничено четырьмя: первые 200 показываются сразу,
остальные доступны через «Показать ещё работы». Сортировка
«По последствиям» отражает порядок сравнения; остальные сортировки,
поиск и фильтры работают как обычно.

Возврат ко всем работам не записывает данные. После очередного
изменения длительности или зависимости список рассчитывается заново,
и прежний фильтр не остаётся активным. Проверки: полный ID-набор
за пределом короткого обзора, неизменность исходных расписаний,
запрет неявного Save и реальный Windows-переход при двух изменениях.


## Изменение критического пути без сдвига даты

Расчёт последствий учитывает не только сдвиг финиша и контрольного
срока, но и переход работы на критический путь или выход с него.
Это важно при изменении параллельных веток проекта: окончание
конкретной работы может остаться прежним, а её резерв исчезнуть.

Работы, ставшие критическими, поднимаются в списке для проверки
после просроченных контрольных сроков. Для каждой работы показано
«Теперь на критическом пути» или «Больше не на критическом пути».
Уже существующие работы, изменившие критический статус, не скрываются
за ограничением короткого обзора; новые работы не выдаются за
ранее существовавшие. Данные проекта при просмотре не изменяются.

Регрессии: два реальных CPM-расчёта с появлением/исчезновением
критичности без сдвига даты, добавление более длинной независимой
работы, сравнение неизменённых входных снимков. Windows-квалификация
проверяет критическое изменение без сдвига и длинный перечень
изменений при пересчёте большого проекта.


## Причина расчётного нарушения срока в таблице

Таблица работ теперь не ограничивается сообщением «Позже срока».
Когда у проекта есть дата начала и CPM-финиш работы позже её
контрольного срока, Atlas показывает число календарных дней отставания,
записанную длительность и непосредственные предшествующие работы,
которые определяют самое раннее начало. Их названия открывают
существующий редактор работы. Команда «Изменить срок или длительность»
открывает ту же обычную форму для самой просроченной работы.

Несколько равнозначных предшественников отображаются как отдельные
переходы; при длинной цепочке список сокращается с указанием
оставшегося количества. Отсутствие даты начала, отсутствие
контрольного срока и выполнение ровно в срок не создают ложного
уведомления. Расчёт использует UTC и правильно учитывает високосные
даты. Просмотр и переходы не записывают проект автоматически.

Windows-квалификация: установленный Atlas, 820 × 650, открытие
предшественника из причины риска, возврат, открытие исправления,
отсутствие записей до ручного Save, сверка после перезапуска.


## Переход к единственной найденной работе

Поиск работ поддерживает клавишу Enter: если в таблице ровно одна
подходящая запись, Atlas переносит к ней фокус и прокручивает
существующую таблицу до физически видимой строки. Поиск с двумя
и более результатами Enter не перехватывает. Для длинного проекта
не требуется вручную открывать очередные порции из 200 строк.

Команда работает без изменения проекта, сохранения данных или
добавления отдельного каталога. В Windows проверяется настоящий ввод
Enter в установленном приложении, открытие работы №1080 и
сверка нативного Store до и после перехода.


## Критический путь в таблице работ

К существующему переходу «Позже контрольного срока» добавлен
компактный фильтр «Критический путь: N». Число работ и их состав
берутся из того же расчёта CPM, который показывает зависимости
и диаграмму. Теперь можно увидеть каждую критическую работу
непосредственно в таблице, даже если дата начала проекта не задана
и календарные сроки ещё не вычисляются.

Список остаётся полноценным: при более 200 работах действуют
существующая пагинация, поиск, сортировка и редактор. В карточке
работы появляется подпись «Критический путь». Снятие отбора
восстанавливает остальные работы; переключение проекта или
открытие списка последствий не сохраняет фильтр предыдущего проекта.
Критический путь является расчётом зависимостей и длительностей,
а не подтверждением факта исполнения или готовности релиза.

Регрессия проверяет большой проект с более 200 критическими работами,
идентичность набора каноническим строкам плана и отсутствие изменений
в исходных данных. Windows проверяет активацию фильтра при 820 × 650,
реальное открытие критической работы и возврат к полному списку
с неизменным нативным Store.


## Переключение между отборами работ

Отбор критического пути, список последствий изменения плана,
проверка просроченных работ и очередь незавершённых зависимостей
теперь взаимно исключают старое специальное выделение.
Если пользователь выбирает другой маршрут, прежняя проекция
больше не скрывает подходящие работы по неочевидному пересечению.

После выхода из таблицы снимаются временные специальные фильтры.
При переходе от списка последствий к обычному виду возвращается
понятная сортировка по названию вместо скрытой сортировки по
последствиям. Существующие сохранённые данные, состав проекта
и расчёт CPM не изменяются.


## Доступность пояснения просрочки в Windows

Испытание установленного Atlas показало, что WebView2 может рисовать
пояснение срока, но не передавать его статический текст в Windows
UI Automation. Теперь доступное название команды исправления содержит
название работы и точное количество календарных дней отставания.
Это помогает пользоваться программой через средства доступности,
не меняя привычный вид строки и не выполняя сохранение.

Нативная проверка требует конкретное наблюдаемое значение через
доступный Windows-элемент, физически открывает предшественника и
форму исправления, затем повторно сверяет Store.


## Переход к строкам результатов без длинной прокрутки

В компактном окне Windows после поиска по каталогу 44 найденные работы
могут находиться ниже большого блока фильтров. Счётчик результатов
показывает число, но для открытия любой работы приходилось прокручивать
страницу.

В закреплённой строке результатов добавлена команда «К работам».
Она переводит фокус к первой найденной работе, используя существующий
механизм перехода и постраничного показа. Команда доступна для поиска
по названию, этапу и источнику, а также при отборах по срокам и
критическому пути. При нуле результатов команда отсутствует.
Применение фильтра и переход не записывают данные.

Нативная Windows-проверка на ранее принятом большом проекте вводит
«project-5 directory-23», получает 44 записи, физически нажимает
«К работам», затем открывает первую видимую совпавшую работу и
подтверждает неизменность Store.


## Прямой переход к срокам из обзора проекта

В заголовке «Состав проекта» теперь рядом с уже существующей
командой «Позже срока» показывается количество работ на критическом
пути и команда перехода к ним. Оба списка формируются из действующего
расчёта CPM, не требуют GitHub и не смешивают подтверждённые результаты
с плановыми сроками.

При переходе открывается существующая таблица. Снимаются прежние
несовместимые фильтры и поисковая строка, первая подходящая работа
прокручивается в видимую область даже при сотнях результатов.
Таблица сохраняет обычную пагинацию, редактор и команды возврата.
Сам переход не изменяет проект и не сохраняет его.

Нативная проверка Windows: на первом экране 820 × 650 видна
команда критического пути; по ней открывается список работ,
физически доступна работа, открывается и закрывается её редактор,
проект остаётся неизменным. После возврата в обзор так же проверяется
существующий переход к работам позже контрольного срока.


## Возврат из длинного списка работ и порядок первого результата

При переходе из обзора к критическим работам или нарушениям срока
Atlas теперь выделяет первую работу в действующей сортировке таблицы,
а не первую в техническом порядке расчёта графика. Поэтому обычный
список из 200 строк не разрастается ради случайной глубокой записи.
Если выбрана сортировка по последствиям, перед переходом восстанавливается
обычная сортировка по названию.

В закреплённой полосе отобранных работ появилась команда «К обзору».
Она возвращает на первый экран даже после открытия и закрытия далёкой
работы, когда верхние вкладки вышли за пределы окна. Возврат не
сбрасывает сохранённые данные, не создаёт записи и не запускает
пересчёт вне прежнего представления. Нативная проверка требует
физической доступности команды на экране 820 × 650 и неизменности Store.


## Исправление расчётной просрочки непосредственно из обзора

При наличии датированного нарушения контрольного срока в начале
«Состава проекта» показываются две работы с наибольшим расчётным
отставанием. У каждой видны срок, расчётное окончание и число дней
расхождения. Если раннее начало ограничивает записанная предыдущая
работа, её можно проверить в том же существующем редакторе.

«Исправить работу» открывает штатную форму напрямую, без поиска
и промежуточного фильтра таблицы. После ручного изменения длительности
или даты Atlas пересчитывает существующий план, показывает последствия
в разделе работ и предлагает явно сохранить новую редакцию. Просмотр,
сравнение и переход к редактору не записывают данные.

Это расчёт календарных дней по зависимостям, а не утверждение о
фактическом нарушении исполнения, выполнении задач или приёмке.
Используются прежние CPM, Store и редактор, без дополнительных прав,
скрытой записи или нового движка.


### Сквозная проверка большого плана

К новому переходу из обзора добавлена адресная исполняемая регрессия:
реальные 1212 работ в тестовом портфеле, расчёт проблемного срока и
ограничивающего предшественника, существующая форма правки работы,
пересчёт по каноническому CPM, устранение нарушения контрольного срока,
экспорт и обратное чтение штатного архива .iwxa. Отдельно сравниваются
неизменённые исходный и промежуточный снимки. Проверка не заменяет
нативную приёмку доступности элементов Windows.


## Изменение критической связи из обзора

В обзор добавлен один конкретный участок записанного критического пути:
работа, ограничивающий её старт предшественник и расчётная длина проекта.
Он появляется только для реальной ограничивающей связи из канонического
CPM, не приписывает одному пути исключительное влияние при параллельных
цепочках. Доступны переходы к обычному редактору длительности и к
сфокусированной схеме зависимостей.

В схеме для выбранной работы можно добавить предшественника или убрать
конкретную связь без поиска в сотнях строк. Удаление подтверждается,
изменяет черновик, заново сравнивает графики до и после, показывает
сдвиг сроков и смену критичности в том же разделе работ. Для записи
по-прежнему требуется отдельное сохранение. Общий механизм CPM и
хранилище не дублируются.


## Поиск предшественника в большом проекте

Форма «Добавить предшественника» в выбранной работе использует
существующий быстрый поиск по всем доступным работам, включая
записи за пределами первых 12 строк. До выбора значение пустое:
первая работа больше не назначается предшественником по умолчанию.
Сохраняются прежние проверки действительности связи, отсутствие
циклов, отдельное подтверждение и запись только в черновик.


Проверка прежнего маршрута добавления предшественника обновлена под
явный выбор. Раньше первая запись выбиралась автоматически; теперь
список содержит пустое начальное значение, и отправка без выбора
отклоняется. Сохранены проверки повторного добавления, отсутствующего
объекта и циклических связей.


## Предварительная оценка удаления критической связи

Перед удалением первой связи у выбранной работы Atlas показывает
результат пробного пересчёта по действующему CPM: останется ли прежней
продолжительность проекта, что произойдёт с датой его окончания,
сколько работ и критических статусов затронет изменение. Если работу
удерживает несколько равнозначных предшественников, удаление только
одного из них может не изменить общий срок. Atlas показывает нулевое
сокращение честно, без обещания ускорения.

Пробный вариант живёт только в памяти представления, не меняет
проект, редакции, зависимости и Store. Удаление требует отдельного
подтверждения, а запись нового плана - отдельного сохранения.
Проверки содержат и неизменный срок при параллельной критической
цепочке, и настоящее сокращение при единственной ограничивающей
цепочке.


## Сквозная приёмка изменения критической связи в установленном Atlas

В штатную Windows-квалификацию добавлен заключительный маршрут на
ранее сохранённом большом проекте: перейти из обзора к критической
работе с длинным названием; открыть её действительную связь;
прочитать предварительный расчёт без записи в Store; убрать один из
пяти равнозначных предшественников с подтверждением; увидеть, что
общий срок остался прежним; отдельно сохранить изменение; выполнить
холодный перезапуск и сравнить всю восстановленную структуру с
ожидаемым проектом, отличающимся ровно одной связью.

Скрипт использует только установленное Windows-приложение, штатный
UIA/WebView2, реальные кнопки и сохранения. Запуск этой квалификации
нужно выполнить на Windows; наличие скрипта и Node PASS не заменяют
результат установленного интерфейса.


## Прогноз для выбранной связи, а не для соседней

В работе с несколькими предшественниками расчёт теперь привязан к
явно выбранной связи. Изначально показан первый предшественник, а
«Другие связи» позволяют переключиться на любой другой. При выборе
показывается его имя, свой предварительный CPM и только одна команда
удаления именно выбранной связи. Переключение не записывает проект.
При переходе к другой работе выбор сбрасывается.

В обзоре рядом с первой выбранной критической связью отдельно
указывается число других равнозначных ограничивающих работ, чтобы
не создавать ложное впечатление, что удаление одной гарантированно
сократит срок.
