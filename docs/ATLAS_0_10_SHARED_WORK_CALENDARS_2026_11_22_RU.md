# IWXA Atlas 0.10: общая библиотека рабочих календарей портфеля

Дата: 22.11.2026. Ветка реализации: `work/2026-11-22-atlas-0-10-calendar-scenario`. Статус: рабочая функциональность до квалификации, **не релиз 0.10**.

## Проблема и предметная граница

Сохранённые `Project.calendarDrafts` позволяют хранить отдельный сценарий для конкретного проекта. Для многопроектного управления важно один раз записать общий график работы и пользоваться **одной точно названной редакцией** в разных проектах. При пересмотре графика нельзя незаметно изменить ранее рассчитанные даты и исторические сценарии.

Создана **локальная библиотека портфеля Atlas**, а не новый Store, Kernel, IAM, Task Engine, Router, корпоративное утверждение или федеральный производственный календарь. Корпоративные права, утверждение и делегирование остаются у исходного Admin Center и T3. Наличие ссылки на документ не означает, что документ независимо проверен и календарь утверждён.

## Новые предметные объекты

Необязательное верхнеуровневое `calendarLibrary[]` в действующем `atlas.project/1`. Записи содержат:

- `id`: устойчивый ID одной серии редакций;
- `version`: целая самостоятельная версия 1..8, неизменяемая после записи;
- `name`: название не более 120 символов, уникальное среди последних редакций разных серий;
- `weekdays`: набор UTC 0..6, не менее одного рабочего дня, без повторов;
- `excludedDates`, `additionalWorkingDates`: явные даты `YYYY-MM-DD`, максимум 1000 каждого типа; пересечения запрещены;
- `source`: обязательная пометка `entered_by_user` (ручной ввод без основания) либо `document_reference` с непустой, предоставленной пользователем ссылкой/реквизитами (не более 320 символов). Это **записанный источник, не автоматическая проверка его подлинности**;
- `recordedAt`: время создания конкретной редакции.

До 32 календарей и до 8 редакций каждого. Исправление календаря **добавляет** новую редакцию, сохраняя старую. Выбор устаревшей версии для редактирования блокируется ошибкой `Stale calendar version`. Библиотека существует в сохранённом Atlas-портфеле, не в другом сервисе.

Необязательное `Project.calendarDrafts[].calendarBasis={id,version}` привязывает самостоятельный сценарий к **одной** редакции из общей библиотеки. При записи нового сценария ядро сравнивает каждое правило с сохранённой редакцией. Если источник недоступен либо правила расходятся, выдавать ложную связь запрещено. Сценарий можно сохранить как **независимый** вариант без `calendarBasis`.

Старые сценарии без `calendarBasis` и старые проекты без `calendarLibrary` продолжают открываться. Историческая ссылка на утраченную библиотечную запись сохраняется при импорте для разбора, но её нельзя использовать для новой записи как действительный источник.

## Пользовательский путь

В существующем разделе «График» → «Сценарий: рабочая неделя» открыть «Календари портфеля». Назвать календарь, выбрать основание, задать рабочие дни и явные исключения, нажать «Добавить календарь в портфель», затем штатное «Сохранить»/Ctrl+S. Это две разные операции: сначала черновик, затем реальная запись в Rust Store по CAS.

Чтобы переиспользовать существующий календарь, выбрать точную редакцию и нажать «Применить редакцию в сценарии». Это **не выполняет запись**, а загружает правила в калькулятор. Сохранение проекта как именованного сценария отдельно фиксирует версию источника **только при совпадении правил**. Ручное изменение после применения календаря делает сценарий независимым. Для следующей версии самого календаря предусмотрено действие «Создать новую редакцию календаря»; старые записи остаются неизменными.

Сценарий по-прежнему не является новым утверждённым планом и не меняет `Work.estimateDays`, исходный CPM, портфельные сроки, Event/Result и права T3. Отдельные `durationUnit` в действующий Work не добавлены. Единый календарный CPM для Ганта и портфеля — следующая предметная задача после приёмки библиотеки.

## Встроенные проверки и ожидаемые свидетельства

Исходные:

- Неизменность сериализации старых `atlas.project/1` без `calendarLibrary`;
- исходные и последующие версии сохраняются отдельно, нет тайного изменения старой редакции;
- календарь можно связать с несколькими проектами по одному `id/version`;
- нельзя выдать неверные или изменённые правила за документированную редакцию;
- календарная дата не выдумывается, юридическое утверждение не подставляется;
- ошибки версий, дат, дублей, источников, превышения лимитов и недоступных редакций;
- настоящий `.iwxa` ZIP roundtrip (проект, сценарий, источник, библиотека);
- открытие и сохранение полей настоящей стабильной 0.8 на неизменном релизном SHA `6ef7b8fa`;
- TypeScript/Vite, original T3, Center, единый `dist`.

Windows (интеграционная ветка без отдельного выпуска):

1. Установленный через оригинальный Setup Core Atlas на окне 820×650.
2. Создание локального календаря реальными UIAutomation-действиями, физическая доступность поля имени и кнопки.
3. Отсутствие native-write до явного Save.
4. Проверка `head.json.root.calendarLibrary`, сохранность прежнего SHA блока проекта.
5. Холодный перезапуск; возврат к «Графику», выбор редакции, применение и **отсутствие повторной записи**.
6. Не объявлять PASS до завершения всех шагов.

## Дальнейший маршрут

1. Исправить все выявленные реальные ошибки, принять исходный и Windows маршрут.
2. Подключить независимый импорт сохранённого каталога в установленную 0.8; исходные тесты не заменяют нативную приёмку.
3. Перейти к предметной схеме Work с единицей длительности и явными календарями, с безопасным сохранением старой трактовки `estimateDays`.
4. Расчёт Ганта, таблицы, портфеля, критического пути и истории вести **из одного календарного источника**. Ни сценарий, ни календарный справочник не подменяют факт выполнения, подписанный Result, доступность ресурсов или полномочия заказчика.

Стабильная `release/0.8` и интеграционная `work/2026-11-16-atlas-0-9-t3` не изменяются. Оригинальные T2/T3, их права, архив `.iwxa` и собственный Atlas Native Store сохраняются.
