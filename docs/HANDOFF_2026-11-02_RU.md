## 2. Смысл продукта, который нельзя потерять

Atlas — одна универсальная система проектного управления для частных лиц, бизнеса, исследований и предметных доменов IWXA. Может работать самостоятельно без ИИ и позже интегрироваться в Personal Agent через существующие права/хранилище. Atlas **управляет проектом, но не исполняет задачи**: Hermes, Goose, Codex, Task Engine и человек — независимые разрешённые исполнители.

Главный вид: **что должно быть / что фактически известно / происхождение и достоверность / разрывы / предложения и утверждённые изменения / сроки, ресурсы, риски / межпроектные зависимости / последствия для портфеля**. Заявление пользователя, зелёный CI, работа в состоянии done или новая Git-ревизия **не являются независимой приёмкой результата**. Не формировать ложный процент готовности без критериев и подтверждения.

Не дублировать Kernel, Host, Personal Agent, Programs Center, Task Engine, корпоративный RBAC, MCP host, второе плановое хранилище или второй движок исполнения.

## 3. Что реализовано в публичном продукте

- `src/core.mjs`: проект/этап/работа/зависимость/решение/риск/источник, валидация, JSON-совместимость `atlas.project/1`. Новые решения `kind:"plan_review"` и привязки заявок валидируются без разрушения старого формата.
- `src/planning.mjs` и `src/vendor/toposort.mjs`: CPM, критический путь, даты, резерв времени, MIT attribution; календарные дни, не ресурсная оптимизация.
- `src/portfolio.mjs`, `src/portfolio-cascade.mjs`, `src/portfolio-schedule.mjs`: межпроектный DAG, влияние блокировок, риски сроков и плановая очерёдность.
- `src/trace.mjs`, `src/impact.mjs`, `src/response.mjs`: обязательные требования, заявленные факты, SHA/freshness, противоречия, предложения изменений, утверждения человеком, связанные работы и история решений.
- `src/github-public.mjs`, `src/source-observation.mjs`, `src/public-refresh.mjs`: публичный read-only GitHub, owner/repo/branches discovery, SHA, неполные страницы, dedup/bounded portfolio refresh, fair queue, rate limit, provenance, одно сохранение на проход.
- `src/storage.mjs`: **одно native IndexedDB хранилище** с миграцией localStorage, миграционной/резервной версией, контролем целостности, откатом, обнаружением конфликтующих вкладок, JSON export/import; не Dexie и не второе хранилище.
- `src/graph.mjs`, `src/visual.mjs`, `src/portfolio-command.mjs`: встроенные SVG/таблица/таймлайн и портфельная очередь проблем; много экранов уже переведены с технических prompt на формы.
- `src/revision-review.mjs`: показывает старый/новый SHA, активные устаревшие evidence, точечный переход, перепроверку на конкретном SHA с историей `reviewOfFindingId`.
- **Новый этап:** `src/plan-review.mjs` — реальная очередь последствий повторной проверки: исходный проект + транзитивно зависимые проекты, незавершённые работы, существующие утверждённые изменения, маршруты влияния. Каждый затронутый проект получает **собственное человеческое решение**: оставить план / предложить пересмотр / отложить. Решение связано с конкретной находкой и SHA, сохраняется в старом журнале решений; предложение создаётся в старом `changes` со статусом `proposed`, утверждение и исполнение не происходят автоматически. Изменение исходного SHA блокирует устаревшее решение до новой перепроверки.
- `src/editor.mjs` и `src/app.mjs`: подключены понятные формы пересмотра и создания заявки, с проверкой текущих оснований. Отдельных прав, исполнительного контура и хранилища нет.

## 5. Инженерные решения и ограничения

- Одно хранилище, один реальный UI. Совместимые опциональные поля в `atlas.project/1`; не создавать второй «реестр последствий» или автоматический изменятель планов.
- Зависимость между проектами **плановая**, а не подтверждение отгрузки. Влияние перепроверки — повод изучить последствия, не автоматически доказанный ущерб.
- Источник прав остаётся внешним. Интеграция Admin Center/T3 откладывается; никакого локального корпоративного RBAC в standalone.
- React Flow, Cytoscape.js, Frappe Gantt, Dexie и другие кандидаты не надо устанавливать пакетом. Использовать, только если практическая польза подтверждена и не появляется вторая конкурирующая модель/хранилище.
- Не пытаться хранить чувствительную медицинскую/корпоративную информацию в публичных фикстурах или незашифрованном standalone storage.
- В `.github/workflows/public-qualification.yml`: обычные pushes запускают быстрый Node CI. `[browser-accept]` запускает staged Chromium Linux → Windows/macOS после Node PASS; `[scale-accept]` отдельно запускает Linux public-scale. Никаких бесполезных повторных Actions; Codex только для независимой финальной приёмки.
- Локальное GitHub-клонирование может не работать из-за DNS: выполнять исходные изменения через разрешённые GitHub connector tools, точный HEAD/TREE и optimistic non-force update.
