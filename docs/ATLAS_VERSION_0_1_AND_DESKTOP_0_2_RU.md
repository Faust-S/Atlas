# IWXA Atlas — фиксация версии 0.1 и начало Desktop 0.2

## Неизменяемая основа 0.1

- Ветка: `release/0.1`, от `addee450b8d80f8fad1fcb9af8e8d13dc1824151`.
- TREE: `381babea0e8d3e7ca73b21ec60b9cd24b5e8e0fd`.
- Действующий `package.json`: `0.1.0`.
- Последняя подтверждённая приёмка исходной версии: GitHub Actions [41422776684](https://github.com/Faust-S/Atlas/actions/runs/41422776684), `127/127 Node PASS`; Windows/Linux/macOS Chromium — 15 этапов PASS и IndexedDB 7/7 на каждой ОС.
- Это принятая **локальная веб-основа**, а не утверждённый Windows EXE. Production release 0.1 в смысле установщика отсутствует.

## Начало 0.2

- Ветка: `work/2026-11-02-atlas-desktop-0.2`, начата строго от указанного 0.1 HEAD.
- Технологический выбор владельца: Tauri 2, минимальный Rust, React 19/TypeScript, Vite; системный WebView2 Windows.
- Новая оболочка вызывает оригинальные `src/*.mjs`, а не копирует CPM, требования, граф зависимостей, human review или ресурсы.
- Нативный store в `desktop/src-tauri/src/lib.rs` — **единственный авторитетный store для самостоятельного Atlas 0.2**, с историей, неизменяемыми блоками, проверкой целостности, конкурентным поколением и явным сохранением.
- Исходная 0.1 IndexedDB реализация оставлена нетронутой в корне репозитория для совместимости/архива. Это альтернативный контур 0.1, не второй работающий store внутри desktop 0.2.
- Старые JSON снимки `atlas.project/1` проверяются и импортируются, сохраняются прежние идентификаторы/связи/доказательства/история. У портфеля в текущем контексте один нативный владелец записи.

## Не приписывать неподтверждённые свойства

В контейнере этой сессии отсутствуют Cargo/Rust и прямой GitHub DNS, однако GitHub Windows runner выполнил Tauri/NSIS сборку, 5/5 нативных тестов файлового хранилища и проверку появления окна Windows: [Actions #41446391609](https://github.com/Faust-S/Atlas/actions/runs/41446391609). Кандидат EXE и NSIS получен; работа с проектом в реальном WebView2, перезапуск с readback и установка остаются отдельными проверками. Это **не production release**.

Agent Workspace, Admin Center/T3, онлайн-слой T4+ и `.iwxa` обмен остаются архитектурными границами без реализации в этом цикле. Для Agent не создаются новые права, Task Engine, Host или Core.

## Пользовательский маршрут 0.2

Открыть Atlas из меню программ → создать проект или импортировать 0.1 JSON → требования → работы/зависимости → сохранить → прочитать обратно → закрыть и открыть → изменить работу → оценить последствия → предложить изменение → утвердить → применить → сохранить новую редакцию.

Достоверность: заявленный факт, GitHub SHA, собственная перепроверка, human decision и применённый план — разные состояния.

Следующие этапы: реально собрать/испытать Windows Desktop; завершить надёжность сохранения/импорта и штатный жизненный цикл; затем доводить табличный/Gantt/graph UX и фирменный дизайн IWXA без копирования всего CSS Agent.
