## Назначение

Atlas — самостоятельное локальное приложение для управления проектами. Не требует Personal Agent, Task Engine, Python, локального HTTP-сервера или Интернета для просмотра и редактирования сохранённых проектов.

Desktop-оболочка: **Tauri 2 / Rust / системный WebView2**. Интерфейс: **React 19 / TypeScript / Vite**. Алгоритмы проектов, CPM, зависимостей, требований/фактов, пересмотра планов, заявок и ресурсов импортируются непосредственно из `../src/*.mjs` и не дублируются.

Публичная сверка GitHub — **только по явному запросу пользователя** и требует сети. Она возвращает наблюдения, а не подтверждение готовности.

## Сборка для Windows

Требуются Node 22+, Rust toolchain с MSVC target (версия, совместимая с Tauri 2.12.3), Microsoft C++ Build Tools, WebView2 Runtime и Windows SDK.

```powershell
cd desktop
npm install
npm run build
npm run desktop:build
```

Итоговый установщик ожидается в `src-tauri/target/release/bundle/nsis/`. Кандидат NSIS подтверждён в CI. Установка и реальный end-to-end маршрут нового выпуска остаются HOLD.

Режим разработки: `npm run desktop:dev`. Vite используется **только во время разработки**. Выпущенное приложение загружает локальный frontend из пакета; сервер в рабочем приложении не нужен.

## Сохранение

Единственный desktop store — `app_local_data_dir()/atlas-store-v1` (системный каталог приложения). Он содержит:

- `head.json`: активный индекс портфеля с редакцией и поколением; целостность корневых данных проверяется SHA-256;
- `blocks/<sha256>.json`: неизменяемые проектные блоки, переиспользуемые при сохранении неизменившихся проектов;
- `history/`: предыдущие поколения индекса для восстановления;
- `atlas.lock`: межпроцессная блокировка на время операций.

Сохранение **ручное** (кнопка или Ctrl+S); frontend проверяет результат через повторное чтение. Если ответ `atlas_commit` потерян после фактической записи, интерфейс сверяет текущее поколение и снимок через `atlas_open` **без повторной записи**; кратковременная ошибка readback допускает вторую попытку чтения. При отсутствии подтверждения программа не выдаёт ложный PASS и предупреждает о необходимости перезапуска перед повторным сохранением. Крупный портфель сериализуется для проверки изменений только при смене самих данных, а не при каждом рендере React. Уже при первом сохранении записывается восстанавливаемая точка истории: если первый `head.json` исчезнет или повредится, программа потребует явного восстановления и не откроет пустой портфель. При конкурентном изменении поколения запись отклоняется. Текущий повреждённый индекс не заменяется пустым портфелем: требуется согласованное восстановление из истории. Перед закрытием с несохранёнными изменениями — предупреждение.

Экспорт/импорт — только `atlas.project/1` JSON через **нативные диалоги**, без произвольных путей из интерфейса. Резервная копия сначала полностью записывается во временный файл рядом с выбранным местом, затем публикуется без перезаписи существующего имени; после диалога ещё раз проверяется поколение портфеля. Слишком большой для последующего импорта JSON не объявляется успешно сохранённым. Архив `.iwxa` не создаётся без согласованного контракта. Импорт старого JSON идёт в черновик; перед заменой портфеля нужно согласие человека, затем явное сохранение. Повторно проверяются актуальная редакция нативного хранилища и отсутствие новых правок после системного диалога. При повторном импорте сохраняется прежняя запись происхождения файла. Крупные портфели и списки работ открываются порциями с явным количеством скрытых объектов и кнопкой «Показать ещё».

Не следует считать архив `JSON` эквивалентом защищённой корпоративной резервной копии. Данные локального хранилища не шифруются приложением: используйте системное шифрование устройства и внешний резервный архив.

## Границы реализации

- Пользовательские рабочие экраны: портфель, обзор, таблица, доска, календарная шкала CPM, зависимости, план/факт, изменения, ресурсы, история и источники. Приостановленные и отменённые проекты не дают фиктивных прогнозных дат; последствия распространяются на цепочку межпроектных зависимостей с сохранением исходных плановых дат и указанием первопричины. Gantt зависимого проекта показывает список заблокировавших его предшественников с переходом в каждый исходный проект, не выдавая локальный CPM за доступный срок поставки.
- Формы работают через существующие `editorSpec()/applyEditor()`; утверждение и применение изменения — **разные действия**.
- Установщик собран и устанавливается, но GUI end-to-end и установленная интерактивная версия не приняты. Отдельные обновления, Agent Workspace import, корпоративные права и облачная синхронизация не реализованы.
- Нативные тесты на Windows подтвердили пять сценариев: начальный запуск, атомарная запись и повторное чтение, конкурирующая запись, исчезновение и повреждение индекса, восстановление с карантином. Более широкая производственная приёмка, GUI-readback, безопасность и нагрузки остаются **HOLD**.
- Выполненная ранее браузерная приёмка 0.1 не является тестом нативного Atlas 0.2.
